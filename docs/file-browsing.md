# 容器与镜像的文件浏览、无 shell 终端

phyless 要能浏览任意镜像和任意状态容器里的文件，也要能给没有 shell 的容器开终端。难点有三个：

- **目标里可能没有工具**：distroless、scratch 镜像里没有 `sh`，也没有 `ls`。
- **已停止的容器无法 exec**：而且它的文件系统只在运行时才挂载。
- **daemon 可能是远程的**：phyless 本机的文件挂不进容器；把整个文件系统打包传回来又太慢。实测一个可写层 4.4 GB 的容器，用 archive 或 export 按约 13 MB/s 传输，要 6 分钟以上。

所以设计只用两样东西：一份**由 phyless 自带的 busybox**，加上**只传元数据的 Docker API**。只用标准 API，不依赖存储驱动（不走 overlay2 的目录技巧），本地和远程 daemon 一样能用。

## busybox 从哪里来

- **来源**：Alpine 的 `busybox-static` 静态二进制，覆盖 phyless 发布的四个架构：amd64、arm64、arm（Alpine armhf 版，armv6 和 armv7 都能运行）、386。以 gzip 压缩后嵌入程序（每份约 0.65 MB，以 string 嵌入，只占只读数据段），只在导入调试镜像时解压一次。用 `scripts/fetch-busybox.sh` 更新，版本固定写在脚本里；脚本会拒绝不是由固定 aports commit 构建出来的包。
- **许可证**：BusyBox 是 GPL-2.0-only，见 `backend/internal/docker/debugshell/busybox-NOTICE.md`。调试镜像里也带一份 GPL 原文（`/usr/share/licenses/busybox/COPYING`）；发布包和容器镜像的 `licenses/` 目录里有许可证文本；每个 Release 都附带对应源码（`fetch-busybox.sh --source`）。
- **调试镜像** `phyless-debug:<架构>-<哈希>`：第一次需要时，把对应 daemon 架构的 busybox 打成 rootfs，通过 `ImageImport` 导入成本地镜像。不需要镜像仓库，离线也能用。
- **busybox 卷** `phyless-busybox-<架构>-<哈希>`：用调试镜像创建一个容器（只创建、不启动），把这个空的命名卷挂到 `/bin`。Docker 会把镜像里 `/bin` 的内容复制进空卷，容器随即删除，卷保留下来。之后**任何镜像**起的容器都可以把这个卷只读挂到 `/.phyless`，执行 `/.phyless/busybox`。
- **名字带内容哈希**（busybox 加许可证文本）：busybox 升级后会得到新的镜像和卷，不会复用旧的；phyless 启动时会删除其他版本的调试镜像和卷，正在使用的会跳过。两者被删除后，下次使用时自动重建。

## 浏览时怎么选路

入口是 `fsbrowse`。API 层只调用 `ListImage`、`ListContainer`、`OpenImage`、`ReleaseImage`、`ReleaseContainer`、`Invalidate`。

| 目标 | 做法 | 实测（wsl 远程 daemon） |
|---|---|---|
| 运行中，有 `ls` | 直接 exec 目标自己的 `ls -la`，实时、开销最小 | — |
| 运行中但没有 `ls`，或已暂停 | 浏览容器共享目标的 PID 命名空间，执行 `ls /proc/1/root/<路径>`（目标用 `pid: host` 时换成它的主机 PID）。实时，挂载也能看到 | 首次 0.48 秒，之后 70 到 100 毫秒 |
| 镜像 | 用这个镜像创建浏览容器，执行 `ls` | 首次 0.45 秒（和镜像大小无关），之后约 90 毫秒 |
| 已停止的容器 | 一个浏览容器：它的镜像，加上 `VolumesFrom: [它自己]`（挂载模式继承目标，只读的仍只读；读写共用这一个）。挂载路径直接 `ls`，其余路径先 `ls` 再合并可写层的变更（见下节） | 首次约 4 秒（其中 3 秒是取 changes），之后约 100 毫秒 |
| 从镜像下载文件 | 另外创建一个只创建不启动的容器，用 `CopyFromContainer` 读取，关闭时删除。不复用浏览容器，因为浏览容器可能在下载途中到期 | 75 毫秒 |

一些细节：

- 执行 `ls` 时路径末尾统一加 `/`，这样 `/bin -> usr/bin` 这种软链接目录会列出内容，而不是链接本身。
- `ls` 返回 1 并且有输出时（部分条目读不到）照常返回结果；失败时带上 `ls` 的 stderr。
- 已知某个容器没有 `ls`（它已经有 PID 浏览容器）时，跳过"先试一次 exec"这一步。
- 镜像视图里会隐藏根目录下的 `.phyless`；`/proc`、`/sys`、`/dev` 是运行时挂上去的，镜像里本来是空的，所以直接返回空列表。
- 已停止的容器如果有 bind 挂载的源目录在主机上已经不存在，带卷的浏览容器会起不来（`ErrBoxStart`）。这时非挂载路径改用不带卷的容器继续浏览，挂载路径则如实报错。

## 已停止容器：镜像加变更合并

`GET /containers/{id}/changes`（即 `docker diff`）返回可写层里增删改过的路径和类型（A/C/D），只有元数据，不含内容。sntlbb 有 10.4 万条，约 8.5 MB，3 秒返回。

列某个目录时：

1. 祖先目录或目录本身被删除了，就报"目录不存在"。
2. 在镜像视图里 `ls` 这个目录。容器新建的目录在镜像里不存在，这时以变更为准。
3. 合并：标为 D 的条目去掉；新增的条目加进来；只是内容有变化的目录保留镜像里的元数据；修改过的文件和新增的条目，用 `ContainerStatPath`（只返回元数据）补齐大小、权限和时间。每个目录最多 stat 256 个，并发 8，超时 30 秒；结果缓存在这个容器的变更集里。

变更集的缓存：

- 内存里按路径排序；查子项用二分定位前缀范围，遇到子目录直接跳过整棵子树，所以列根目录不用扫完全部变更。
- 以 `FinishedAt` 校验：容器运行过就失效。phyless 自己往容器里上传或复制文件之后也会清掉。
- 所有容器合计最多 30 万条路径（约 25 MB），超出时淘汰最久没用的；单个容器超出预算时只用这一次、不缓存。每个条目 5 分钟没用就由 timer 释放。
- 获取变更和请求的 ctx 脱钩（超时 1 分钟）：请求断开了，结果照样缓存，重试时直接命中；并发的请求共用同一次获取。

**diff 视图**（文件浏览的"± diff"按钮，`?diff=1`）：直接用同一份变更集，只列当前目录下有变更的子项，保留目录结构（下面有变更的目录也列出），标出 A/C/D；元数据同样用 `ContainerStatPath` 补齐，删除的条目不 stat。不需要浏览容器，运行中的容器也能用；运行中的容器变更集以 10 秒为粒度缓存。普通浏览时前端另发一个不 stat 的 `?diff=marks` 请求，到达后给条目补上 A/C 标签，不阻塞列表；diff 视图中目录带上其下变更种类（`kinds`），供 A/C/D 筛选判断是否保留。挂载点及其内部的条目带 `mount`（类型、来源），显示 volume/mount 标签；下面有挂载点的目录带 `mount_below`，"mount" 按钮据此只显示挂载及其所在目录。diff 不含挂载内容，所以 diff 与 mount 同时开启时取并集。运行中的容器还会在 PID 浏览容器里对每个 `/proc/<pid>/exe` 执行 busybox `readlink`（得到的是目标自己挂载命名空间里的路径），结果按容器缓存 10 秒；匹配的条目带 `run`，其父目录带 `run_below`。用 `pid: host` 的容器看到的是主机进程，跳过。因为 PID 浏览容器不再只在"没有 ls"时出现，"目标没有 ls"改为单独记录。readlink 给出的是真实路径，经软链接目录（如 `/bin -> usr/bin`）浏览时不会打标签。路径是文件（如文件 bind 挂载）而列不出时，前端改为打开所在目录。

局限："删掉后又重建"的目录（overlay 的不透明目录）在 diff 里不一定逐个标出删除，合并后可能还会显示镜像里的旧文件。

## 修改文件：删除、重命名、权限

入口是 `fsbrowse` 的 `Remove`、`Rename`、`Chmod`、`Chown`，全部是 argv 形式（不经 shell），路径在这里统一校验（绝对路径、不能是 `/`），mode 只接受 3–4 位八进制，属主只接受数字 `uid[:gid]`（名字会在辅助容器的 passwd 里解析，结果不对）。

| 目标 | 做法 |
|---|---|
| 运行中 | 先以 root（exec `User: 0`，chown 才能用）执行目标自己的 `rm`/`mv`/`chmod`/`chown`；命令不存在（126/127）才退到 pid 浏览容器里的 busybox，路径加 `/proc/1/root` 前缀。普通失败（权限不足、只读文件系统）如实报错，不回退 |
| 已暂停 | exec 被拒，直接用 pid 浏览容器 |
| 已停止 | 只能改挂载内的路径，用同一个浏览容器里的 busybox。rootfs 路径一律拒绝：辅助容器的 rootfs 是它自己的可写层，写进去会"成功"而目标没变。还拒绝：只读挂载、tmpfs（停止后没有内容）、跨挂载移动 |

所有状态共用的护栏：

- 挂载点本身、以及其下有挂载点的目录，不能删除或移动（`rm -rf` 会先清空卷，再在忙碌的挂载点上失败）。
- 经辅助容器 chmod/chown 时，先用 `ContainerStatPath` 拒绝符号链接：busybox 会在辅助容器自己的文件系统里跟随它。
- 写操作超时 2 分钟（列目录是 30 秒）；取浏览容器时要求它剩余寿命不少于本次超时，所以容器到期不会把 `rm -rf` 打断在半路。被提前替换的旧浏览容器照样到期自删；删除目标容器时按 `phyless.container` 标签把它们一并删除，不会占着卷。
- 运行中容器写完清掉变更缓存；已停止容器只改挂载，挂载不在 diff 里，不清。

compose 和本机配置（宿主文件）的权限修改走 `os.Lchown` + `os.Chmod`，不跟随符号链接（可能指出浏览根目录），`-R` 时跳过链接。

## 浏览容器（`debugshell.Pool`）

- **每个 key 一个**：`image:<镜像ID>`、`pid:<容器ID>`、`stopped:<容器ID>`（加上兜底用的 `stopped-novols:<容器ID>`）。同一个 key 的并发请求只创建一次。
- **配置**：入口是 `/.phyless/busybox`，Cmd 显式写成 `sleep 300`（避免镜像自己的 CMD 被当成 sleep 的参数）；`User 0`、`NetworkMode none`；关闭 healthcheck（否则会定期运行镜像里的程序）；`AutoRemove`；只读挂载 busybox 卷。
- **生命周期**：主进程 `sleep 300` 结束时容器自己退出并删除。剩余寿命不足本次操作的超时（列目录 30 秒、写操作 2 分钟）时，换一个新的。phyless 崩溃也不会留下残留，不需要 GC 协程。map 里过期的条目在每次新建时清理。
- **创建和请求脱钩**：创建过程单独设超时，不受请求取消影响，所以不会留下"已创建但没启动"的容器（`AutoRemove` 只有启动后才生效）。
- **自愈**：容器意外消失（NotFound 或 Conflict）时重建一次。exec 返回 126/127 说明 busybox 卷是空的：这种情况只会在卷被删除、恰好又被 Docker 自动建成空卷时出现。这时先删除浏览容器和这个卷，再重试一次，重试时会重新填充卷。
- **释放**：删除镜像之前，按 `phyless.image` 标签删除钉住这个镜像的所有辅助容器，包括其他 phyless 实例的。删除容器之前，按 `phyless.container` 标签删除它的所有浏览容器（含被提前替换、尚未到期的），避免卷一直被占用、`rm -v` 删不掉。

## 无 shell 终端

终端请求的 shell 是绝对路径（默认 `/bin/sh`），用 `ContainerStatPath` 确认它在目标里不存在时，自动进入调试模式：

- 调试容器用调试镜像创建，共享目标的 PID 和网络命名空间，加 `SYS_PTRACE` 权限（读取其他 uid 进程的 `/proc/<pid>/root` 需要它）。
- 启动后执行 `busybox --install`（硬链接，不用 `-s`：绝对路径的软链接在 chroot 后会指向目标里不存在的 busybox），后台留一个 `sleep`（PID 记为 K），然后 `chroot /proc/1/root /proc/K/root/bin/busybox sh`。`/proc/K/root` 是魔法链接，chroot 后仍指回调试容器的 `/bin`，而目标的 `/proc` 显示的是共享的 PID 命名空间，所以不用挂载、不加权限、不改目标，`/etc` 等绝对路径就是目标的。`PATH` 把 `/proc/K/root/bin` 放在最前。
- chroot 失败（比如目标没有挂载 `/proc`）时回退到旧模式：不 chroot，只 `cd` 到目标的文件系统目录。两种模式都在终端里用黄字提示。
- shell 就是容器的主进程，用 attach 接入，设置 `StdinOnce` 和 `AutoRemove`：会话结束或 phyless 崩溃时，shell 读到 EOF 退出，容器自动删除。正常结束时还会再显式删除一次。

## 命名、标签和可见性

| 项 | 取值 |
|---|---|
| 容器名 | `phyless-autoremove-<用途>[-<目标>]-<6位随机>`，用途为 `browse`、`shell`、`download`、`busybox-init`；目标是容器名或镜像引用，截短并替换成 Docker 允许的字符 |
| 界面提示 | 列目录用到浏览容器时，响应头 `X-Phyless-Helper`（容器名）和 `X-Phyless-Helper-Life`（闲置秒数）告诉文件浏览器显示「由辅助容器读取、闲置后自动删除」；调试终端在开头打印辅助容器名，并说明退出后自动删除 |
| 标签 | 所有辅助对象都有 `phyless.role=debug`（调试镜像和 busybox 卷也有）；钉住某个镜像的还有 `phyless.image=<镜像ID>`；服务某个容器的（pid、已停止）还有 `phyless.container=<容器ID>` |
| 可见性 | 容器、镜像、卷列表和系统统计都按 `phyless.role` 隐藏；卷的"被谁使用"也不计入浏览容器。在 docker CLI 里能从名字看出它们是什么、会自己删除 |

隐藏的原因：浏览容器每几分钟就换一批，显示出来会让列表频繁变化；避免用户误删正在用的辅助对象；不让辅助对象虚增数量，或者让卷、镜像看起来"被某个陌生容器使用"。self-update 的 `phyless-helper` 用的也是同一个标签（值为 `helper`）。

## 回收时间

| 对象 | 正常情况 | phyless 崩溃时 |
|---|---|---|
| 浏览容器 | 启动 5 分钟后自己删除；删除对应的镜像或容器时立即删除 | 照样 5 分钟后自己删除 |
| PID 浏览容器 | 同上；目标停止时随之结束 | 同上 |
| 终端调试容器 | 会话结束时立即删除 | 连接断开后自动删除 |
| 下载容器、`busybox-init` 容器 | 用完立即删除 | phyless 下次启动时清理，只清理已存在超过 1 小时的（同一个 daemon 上可能还有别的 phyless 实例在用） |
| 调试镜像、busybox 卷 | 常驻，各约 1 MB；被删除后按需重建；旧版本在 phyless 启动时删除 | — |
| 变更缓存（phyless 内存） | 5 分钟没用就释放 | 随进程释放 |

## 没有采用的方案

- **export 或 archive 整个文件系统后建索引**：这是旧方案（`imagefs`）。要把每个字节都传过来，大容器在远程 daemon 上要好几分钟，还要占磁盘做索引。已删除。
- **把 busybox 复制进目标容器**：会修改目标；只读根文件系统、`noexec` 的 tmpfs 都会导致失败；还会留下痕迹。
- **直接挂载 overlay2 的层目录**（已停止的容器）：需要 `--privileged`，只适用于 overlay2；容器被启动时同一个可写层会被两个 overlay 同时使用，属于未定义行为。不够通用。
- **对已停止的容器执行 `docker commit` 后浏览**：可写层很大时既慢，又占双倍磁盘空间。
